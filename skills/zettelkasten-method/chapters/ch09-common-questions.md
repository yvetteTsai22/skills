# Chapter 9: Common Questions — Getting Started, One Box or Many, First Note, When to Split

Sources: https://zettelkasten.de/posts/how-to-start-zettelkasten-when-stuck-in-theory/ · /posts/how-many-zettelkasten/ · /posts/your-first-note/ · /posts/when-start-new-note/ · /posts/no-categories/ · /posts/search-alone-is-not-enough/ · /posts/trust-the-process-nickmilo22/ · /posts/dont-rely-on-source-have-faith-in-yourself/ · Overview "Common Questions" section (all under https://zettelkasten.de)

## Core Idea
Most beginner questions have the same answer: **stop designing and start writing on something you genuinely care about.** Keep one Zettelkasten for life, add no categories, and don't treat the first note as special. Learn only the three basic actions (create, link, find), and grow a single structure note for a single real research interest until you are proud of it. Split notes when getting information out of them takes too long.

## Frameworks Introduced
- **Starting When Stuck in Theory** (Sascha, 2025), the four steps:
  1. Use a minimalist, distraction-free app.
  2. Learn *only* how to create notes quickly, set direct links, and find notes (full-text search and following links).
  3. Create **one structure note** for a current research interest.
  4. **Create notes from a link first**: add a link on the structure note to a note that doesn't exist yet, then create that note.
  - Goal: make the structure note something you would proudly show someone ("Wow, there's a lot in there"). This follows the advice in Waitzkin's *The Art of Learning* to start chess with the king and one piece.
  - The interest must be **genuine**. Dummy or "safe to fail" content makes you shallow and sloppy, because the method cannot be learned with fake material.
  - When it is done, pick the next interest and ask how old notes advance it.
- **One Zettelkasten or many?** (Christian): **one**, for anyone doing life-long knowledge work. Cross-domain serendipity (flowers in 2015 plus bees in 2018 gives notes on pollination or honey) needs a single archive.
  - The only exception is a *throwaway* project box (e.g. a master's thesis) when you will never work in the field again.
  - "If you must, divide by duration of use, not by topic." Never run several boxes meant to last a lifetime.
- **Your first note: don't overthink it** (Christian). The one up-front decision is **project box vs. knowledge-companion box**. A project box stays closed to irrelevant input and can get its introduction last. A companion box stays open, and overview notes come later as "planning after the fact".
- **When to start a new note** (Christian), as a decision tree. See the worked example.
- **Splitting**: a note is too big "when getting information out of it takes too long". Lists of evidence scale fine. Prose notes split. Splitting often yields **three** notes: two extracted details plus the original, repurposed to connect them (like a join table).
- **Safe splitting** (Sascha): when you split, leave a trail. The original ID stays and links to the extracted note. Write link context so later edits don't silently break meaning. "Be cool with errors."
- **Interpret, then trust yourself** (see Ch 5) and **Trust the Process**: the effort itself is the payoff.

## Key Concepts
- **Paralysis by analysis**: designing the system instead of using it.
- **Project (single-topic) Zettelkasten**: a closed, focused box whose notes *are* the draft.
- **Knowledge-companion Zettelkasten**: an open, life-long ecosystem of sub-projects.
- **Link-first note creation**: placing the link before the note exists.
- **Compilation note**: a note gathering existing knowledge plus the new detail, linked both ways.
- **Container note**: a list of evidence used for lookup, not for reading through.

## Mental Models
- **Start small, like the king plus one piece.** Isolate one skill and one topic before you scale up.
- **Order emerges.** Feed the box and structure appears. Correcting course is cheap when the structure is flexible.
- **Your archive is a daimon you train** to see some things as elemental and others as compilations. You will change your mind, and that's fine.

## Anti-patterns
- **Consuming endless theory about the method**: it is the main way people get stuck.
- **Practising on dummy content**: it gives no motivation and teaches shallow habits.
- **Multiple life-long boxes split by topic**: they block cross-connections.
- **Planning the "five most important topics" before the first note**: unnecessary up-front design.
- **Growing prose notes indefinitely**: they violate atomicity and become slow to use.
- **Splitting without leaving a trail**: old links point to content that has moved.

## Worked Example
**"When should I start a new note?"** The site's decision tree, condensed:

```
No notes yet?            -> write anything that fits a note now; splitting skill comes later
Have notes -> search for related ones:
  none related           -> new note, as if the box were empty
  related exist -> read them, then ALWAYS add links:
    don't fit the idea   -> new note, reuse existing keywords
    a few roughly match  -> new compilation note: gather existing notes + new detail,
                            comment, link both directions
    one note is the same -> already covered? done.
                            new reference/detail? add it to that note
```

**Banana-bread split**: a *banana bread* note grows bloated after research. Extract *the bake-ability of bananas* and *what makes a bread a bread* into their own notes. Keep the original as a banana-bread-specific note that links to both. One note becomes three, and each is reusable.

## Key Takeaways
1. Learn three actions (create, link, find), then build one structure note on a real interest.
2. Keep one Zettelkasten for life unless the project is truly disposable.
3. The first note doesn't matter. Your intent (project vs. companion) does.
4. Before writing, search for related notes, then always link.
5. Split when retrieval is slow, and leave link trails when you do.
6. Skip categories and use tags (object tags) plus structure notes.
