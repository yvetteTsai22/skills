# Glossary — Zettelkasten Method (zettelkasten.de)

**Arguments / Counter-arguments** — Premise, operator, conclusion. A counter-argument attacks a premise's truth or the inference's validity. These are two of the six item types to search for while reading (Ch 6)
**Atomicity, Principle of** — A processing direction toward one knowledge building block per note. Keep together what belongs together and separate concerns. It is a compass, not a size law (Ch 1, Ch 6)
**Barbell Method of Reading** — Read once quickly and mark, then process only the marked parts in depth. The text's quality sets the time spent (Ch 6)
**Buffer note** — A loosely ordered list of ID + title + context, collecting notes for a project before they get a place in its structure (Ch 4)
**Building Blocks** — Inbox, note archive, and reference manager. Finished texts sit outside the system boundary (Ch 3)
**Categories** — Exclusive, top-down groupings. The site rejects them in favour of emergent clusters and tags (Ch 3)
**Citekey** — A stable ID for a source in a reference manager, e.g. `mccracken2004bibd` (Ch 6)
**Collector's Fallacy** — Mistaking the saving of material (copies, bookmarks, read-later items) for knowing it (Ch 3)
**Composing / Revising** — Adding new text vs. reshaping or cutting existing text. Do them in separate sessions (Ch 7)
**Coverage / Practice / Insight** — Drill-down learning stages: skim, write in your own words, connect (Ch 5)
**Directional / Indirectional work** — Notes made for a specific project vs. feeding the archive without one (Ch 7)
**Double-hash tag** — `##tag` marks a designated top-level structure note (Ch 4)
**Entry point / Register** — Luhmann's sparse keyword index into central clusters. It was not a tag list (Ch 8)
**Folgezettel** — "Following note": a child filed in a parent's sub-branch. Its connection comes from position (Ch 2)
**Heterarchy / Semilattice** — Structure with cross-branch overlap. It is not a strict tree (Ch 1)
**Hub note** — Luhmann's slip listing places to continue a topic, and the ancestor of structure notes (Ch 2, Ch 8)
**Hypertext** — Notes that reference, expand, and reuse each other. Organic, not linear (Ch 1)
**Inner / Outer form** — Outer: the ID, giving separateness and the possibility of connection. Inner: metadata plus content (Ch 1)
**Irritation / Information / Complexity** — Luhmann's conditions for communication with a slip box (Ch 5)
**Jump mark** — A hidden ID used as a cross-reference anchor in a manuscript (Ch 3)
**Knowledge Cycle** — Research, read, take note, write. Keep cycles short (Ch 3, Ch 7)
**Knowledge vs. information** — Information "just is". Knowledge has context and relevance added (Ch 1)
**Layers of Evidence** — Phenomenon/pattern, then interpretation, then synthesis (Ch 4)
**Link context** — The stated reason for a link. The site calls it "created knowledge" (Ch 1)
**Luhmann-ID** — Branching alphanumeric address: `1`, `1a`, `1a1`, `1b`, `2` (Ch 1, Ch 8)
**Object tag / Topic tag** — A tag for what a note is *about* vs. what it is *relevant to*. Prefer object tags (Ch 3)
**Outline file** — A project container in the archive that references notes by ID (Ch 7)
**Project vs. knowledge-companion Zettelkasten** — A closed single-topic box vs. an open life-long one (Ch 9)
**Structure Note (Structure Zettel)** — A meta-note that orders other notes, like a table of contents. A note can appear in many (Ch 2, Ch 4)
**Time-based ID** — A timestamp such as `202006110955`. Unique, unchanging, and readable as a date (Ch 1, Ch 3)
**Ties, kinds of** — Juxtaposition < categories < tags < Folgezettel and links, with direct links strongest (Ch 2)
**Zettel / Zettelkasten** — "Paper slip" / "slip box". The plural is Zettelkästen (Ch 1)
