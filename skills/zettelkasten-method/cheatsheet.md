# Cheatsheet — Deciding Like Sascha & Christian

## Decision rules
- **Unsure if it's worth a note?** Write it, within your deadline, because you can't know future relevance. *Exception:* dead information with no context. Add relevance first or skip it.
- **Adding a link?** State why in the same sentence. No reason means no link.
- **Adding a tag?** Is the note *about* this object? If yes, tag it. If it's only *relevant to* it, use a structure-note link instead.
- **Tag search returns hundreds of notes?** Time for a structure note. Sascha saw hubs at ~500–700 notes and structure notes at ~1,000–1,500.
- **A Luhmann practice is tempting?** Ask whether paper forced it. If yes, find the principle and use the lightest digital technique.
- **Want order?** Use structure notes (many orders), not Folgezettel (one meaningless order) or folders (silos).
- **Note too long?** If extracting information takes too long, split it into 2 details plus a connector, and keep the old ID.
- **Reading a study?** Record the design and conditions (layer 1) separately from the explanation (layer 2).
- **Source cites only secondary literature?** Take it with a heap of salt and check the primary literature, at least at random.
- **Book feels thin?** Pass 2 of barbell reading takes minutes. Dense book? Take days, deliberately.
- **Starting a text?** Never start from a blank page. Outline, attach notes, fill gaps, paste, rewrite.
- **Mid-draft and you need more research?** Note a research prompt in the project task list and keep composing.
- **Stuck on the method itself?** One genuine interest, one structure note, three skills (create, link, find).

## How many Zettelkästen?
| Situation | Choice |
|---|---|
| Life-long knowledge work, any field | **One** box, everything in it |
| Disposable project, never revisiting the field | Separate project box is fine |
| Two simultaneous throwaway projects | Still one box, since cross-links may help |
| Several boxes "for life" split by topic | Never |

## First note?
| Box type | Rule |
|---|---|
| Project (thesis, single topic) | Closed to irrelevant input, write the intro last |
| Knowledge companion | Open. No note is special and overviews come later |

## Choosing an ID
| Scheme | Use? |
|---|---|
| Time-based `YYYYMMDDHHMM` | **Default (digital)** |
| Luhmann `1a1` | Paper only |
| Random/hex string | Works, loses readability, so not recommended |
| Title as ID | Breaks on rename, so avoid |

## Ties, weakest to strongest
Adjacency/sort order → full-text match → tag → structure-note membership → **annotated direct link**

## Barbell passage triage
| | Easy | Hard |
|---|---|---|
| **Useful** | Process for use and let it inspire writing | Process heavily for understanding |
| **Not useful** | Ignore | Chew briefly ("sharpen teeth"), then drop |

## Thresholds & defaults
- Processing time is up to **2×** reading time.
- Start research cycles at a **1-hour** cap, then adjust.
- Daily writing beats binges: 500/day > 3,500 once a week. An hour or two a day beats one long day.
- Set word targets from your **actual best**, not aspirations (don't set 5,000 if your record is 3,000).
- Compose in your best-focus hours (often mornings) and revise later.

## Tells & smells
- A pile of photocopies, bookmarks, or read-later items is the **Collector's Fallacy**.
- Notes you can't understand a year later need a claim title and an abstract first sentence.
- "I'll figure out how these connect later" is the Collector's Fallacy applied to links.
- Folders per project or topic mean complexity is being capped and interdisciplinary links blocked.
- Endless reading about Zettelkasten theory means it's time to write on a real interest.
- Notes copied verbatim mean nothing was interpreted, so no information was created.
- Expecting the Zettelkasten to write a polished paper: it enhances effort and does not replace editing.
